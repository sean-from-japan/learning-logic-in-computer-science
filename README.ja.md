# learning-logic-in-computer-science

2年次の論理学の科目で何を学んだか、どう勉強したか、そしてその考え方を実行できる形にした小さなライブラリです。

主役は1つ目です。

1. **学習の記録** — 命題論理の構文からモデル検査までの流れについて自分で書いたノートと、第二言語で科目を修めるために組み立てたAI併用の学習方法の記録です。[`docs/study-system.md`](docs/study-system.md) と [`docs/notes/`](docs/notes/) にあります
2. **`logickit`** — 科目で扱った手続きを実装した、依存のないPythonライブラリとコマンドラインです。テストは182件あります

科目の評価は **92/100** でした。結果の伴わない勉強法は主張にすぎませんので、根拠として置いています。これは科目に対する評価であって、このリポジトリの中身は採点対象ではありません。

技術文書の本体は英語の [README.md](README.md) です。この文書は要点だけをまとめたものですので、詳細はリンク先をご覧ください。

## なぜ実装したのか

連言標準形への変換は、書けるようになるよりずっと前から手では実行できていました。**その二つの差が、自分の理解が実際にあった場所です。**

コードにすると、それまで踏み越えていた問いが立ちます。`p` と `¬p` を両方含む節はどうなるのか。空節とは何なのか。`X U ψ` は、`X` が一度も成り立たなくても `ψ` が成り立てば直ちに成り立つのはなぜか。どれも、答えが分かるまで書けない1行でした。

## 全体の流れ

構文から意味論へ、自然演繹へ、そして健全性と完全性へ進みます。健全性と完全性が要になります。`⊢` と `⊨` が同じ論理式を選び出すと述べるものですので、**安いほうを使ってよいという許可**になります。その右側にあるものは、すべて安く済ませる方法です。図は英語の [The arc](README.md#the-arc) にあります。

ノート7本の一覧は [The notes](README.md#the-notes) にあります。命題論理、自然演繹、健全性と完全性、述語論理、連言標準形とDPLLと導出、単一化、時相論理とモデル検査です。すべて自分の例で書き起こしたもので、講義資料は再現していません。

## ライブラリでできること

```bash
pip install -e .
logickit entails "p" --premise "p -> q" --premise "q"
```

主な機能は5つです。実行例は [The library, by example](README.md#the-library-by-example) にあります。

- **論理的帰結の判定** — 成り立たない場合は、前提をすべて真にして結論を偽にする反例モデルを返します
- **DPLL** — 真理値表を作らずに解きます。`--trace` で単位伝播・純リテラル・分岐・矛盾の回数が出ます
- **導出** — 空節を導いて充足不能を示します。手でたどり直せる形で各ステップを出力します
- **単一化** — 最汎単一化子を求めます。出現検査が働く例も含まれています
- **有界モデル検査** — 線形時相論理の性質を検査し、成り立たない場合は反例になる走行を返します

終了コードには意味があります。性質が成り立つ場合が `0`、成り立たない場合が `1`、入力を読めなかった場合が `2` です。モジュールの構成は [Modules](README.md#modules) にあります。

## 動かし方とテスト

Python 3.9以降で、実行時の依存はありません。

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e . && pip install -r requirements-dev.txt
pytest        # 182件
ruff check .
```

テストの大半は、**同じ問いに対する二つの実装の突き合わせ**です。この形でなければ自分でも信用できませんでした。連言標準形への変換は、14個の論理式について**すべての割り当て**で元の論理式と一致するかを検査します。DPLLの判定は真理値表と突き合わせ、得られたモデルは論理式に代入して確かめます。導出の各ステップは独立に導き直して、正当な導出結果であることを確認します。単一化は、置換を両辺に適用して等しくなること、そして最汎であることを検査します。構文解析の結果は出力して読み直しますので、優先順位と括弧付けが黙って食い違うことはありません。

**このうち3つは、最初に走らせたときに落ちました。**2つは `U` と、連言標準形が矛盾に対して何をするかについての、私の予想が誤っていたものです。どちらも訂正をテストに書き込んだ形で残しています。

## 制約

- **真理値表による方法は指数時間です。**意図的にそうしています。DPLLを測るための基準であって、推奨ではありません
- **連言標準形への変換も指数的です。**分配で節の数が増えます。構造を保つ変換なら線形で充足同値になりますが、増大そのものを見るのが目的でしたので実装していません
- **導出は素朴な飽和で、ステップ数の上限があります。**順序付けも support 集合も索引もありません
- **単一化は構文のみで、その上に述語論理の導出は作っていません。**次に作るとすればここです
- **モデル検査は明示状態かつ有界です。**反例は健全に見つけますが、「成り立つ」という判定は上限に対する相対的なものです。本来の検査器は、否定した論理式からビュッヒオートマトンを作り、積の上で受理サイクルを探します
- **時相論理の原子命題に `X`・`G`・`F`・`U` は使えません。**構文解析器が予約しています
- **自然演繹の証明検査器はありません。**意味論の主張は機械的に検査していますが、構文の主張は今も手で確かめています
